System guide

Particles & VFX

Author an effect visually, then fire it from one line of gameplay code. One draw call per emitter, preallocated buffers, and no Object3D per particle — built for a playable ad's frame and size budget.

System
A named group of emitters that play together. What gameplay holds and calls play() on.
Emitter
One shape + sixteen modules. An explosion is a flash and debris and smoke — three emitters, one system.
Module
Emission, Shape, Velocity, Noise, Color, Size… each toggled independently. A disabled module genuinely costs nothing.
1

Create an effect

Open the 3D editor, then click ✨ or press P. The left dock becomes a full-height Inspector, and the particle toolbar appears.

Pick a preset from the dropdown, then ＋ System. With a scene object selected the new effect is attached to it; otherwise it lands where you're looking.

smoke · fire · sparks

The three you'll reach for most. Fire and sparks are additive; smoke is alpha-blended and sorted.

explosion

Three emitters — flash, debris, smoke — with debris spawning smoke on death via a sub-emitter.

coin-burst · confetti

Reward feedback. Gravity-driven, one-shot, tuned to read instantly at small size.

dust · rain · snow

Ambient, looping, world-space. Prewarmed so they start already populated instead of filling in.

magic · energy-burst

Orbiting motes and expanding shells. Additive, bright colour ramps.

hit-impact · trail

Short radial punch, and pooled ribbon trails for anything that moves.

Presets are configurations, not gameplay. "Coin Burst" describes a look — small bright specks thrown upward — not a coin. Using it for a gem or a star is the normal case.
2

The transport

▶ ⏸ ↻ ⏹ ✕ control the live preview. Everything you change in the Inspector shows up on the very next frame — no rebuild, no restart.

▶ Play / ⏸ Pause
Start or freeze the preview.
↻ Restart
Rewind to the beginning. What you press after tuning a one-shot.
⏹ Stop
Stop emitting, but let live particles finish their lifetimes.
✕ Clear
Kill every live particle immediately.
Opening or closing the editor never disturbs a running effect. Playback only changes when you press Pause or Stop — switching modes, or leaving the editor entirely, leaves effects running exactly as they were.
3

Pick an emission shape

Box

A volume. Ambient dust, rain and snow falling through a region. Set Thickness to 0 to emit from the surface only.

Sphere

Radial. Explosions and bursts. Thickness: 0 emits from the shell, which is what makes a burst read as one expanding ring rather than a filled cloud.

Cone

Directional. Fire, smoke, jets. Cone Height above 0 spreads the spawn along the axis, so a column starts already filled.

Every shape emits about local +Y, so "fire rises" is the zero-rotation case. Arc restricts the circumference — a half-sphere needs no separate shape.

4

Fire it from gameplay

The common case is one line — move the effect to a point and replay it.

import { Ion } from "../engine/Ion";

// Find it by the name you gave the system in the editor.
const burst = Ion.particles.getByName("Coin Burst");

// playAt = move there + restart. What a pickup handler wants.
burst?.playAt(coin.object3D.position);

Wired to a real event, using the collider system from the previous page:

export class PickupFx {
  private readonly burst = Ion.particles.getByName("Coin Burst");
  private readonly impact = Ion.particles.getByName("Hit Impact");

  wire(): void {
    const zone = Ion.colliders.getByName("CoinZone");
    zone?.onTriggerEnter("Player", (other) => {
      this.burst?.playAt(other.worldCenter);
      this.impact?.playAt(other.worldCenter);
    });
  }
}

For finer control, reach the individual emitter:

const system = Ion.particles.getByName("Explosion");
const debris = system?.get("Debris");        // by emitter name

debris?.emit(40);                            // ignore rate/duration, fire now
debris?.settings.main.startSpeed.max = 14;   // live config — takes effect next frame

if (system?.isFinished()) {                  // stopped AND fully drained
  // safe to reuse or release
}
5

Local or world space

The one setting that changes what an effect means. It's in the Main module.

local

Particles move with the emitter. A torch flame attached to a moving hand. Rotating the emitter drags its existing particles along.

world

Particles are released and left behind. Exhaust, smoke trails, footstep dust. The emitter's later movement doesn't touch them.

Changing this at runtime clears the live particles — they're expressed in the space being left and would visibly teleport otherwise.
6

Sub-emitters

One effect spawning another, without gameplay code sequencing it. In the Sub Emitters module, add an entry and pick a sibling emitter by name.

On Birth
Fires as each particle spawns. Trails, sparks leaving a projectile.
On Death
Fires as each particle expires. Debris → smoke is the classic.
On Collision
Fires when a particle hits the collision plane. Splashes, impact puffs.

Chance keeps it from firing on every single particle (0.25 on a 70-particle burst is plenty of smoke), and Inherit Vel carries some of the parent's momentum into the child. Chains are depth-limited to 3.

7

Keep it cheap

The Diagnostics panel at the bottom of the Inspector is measured, not estimated — active/max particles, draw calls, real buffer bytes, and the actual milliseconds spent in the last update.

Biggest single cost
Overdraw — large, overlapping particles
Cheapest way to halve it
Lower Rate, not Max Particles
Sorting
Only for alpha blending — leave off otherwise
Noise octaves
Each one is another sample per particle per axis
Trails
A 32-point trail is 16× the particle's own cost
Off-screen ambient effects
Set a Cull Distance in Quality/LOD

Scale everything at once from a device check at boot:

// Scales emission rate and burst counts across every effect —
// the same authored effect, running thinner.
Ion.particles.setQuality("low");     // "high" | "medium" | "low"

const stats = Ion.particles.getStats();
console.log(stats.activeParticles, stats.drawCalls, stats.lastUpdateMs);
Additive blending doesn't need sorting — draw order is mathematically irrelevant for it, so the sort would be pure cost. Turn By Distance on only for alpha-blended, overlapping smoke.

Full API

Registry — Ion.particles
getByName(name: string): ParticleSystem | undefined By the system name from the editor.
setQuality("high" | "medium" | "low"): void Scales rate and burst counts across every effect.
getStats(): ParticleStats Active/max particles, emitters, draw calls, buffer bytes, last update ms.
playAll() · pauseAll() · clearAllParticles() Blunt instruments for a cutscene or a pause menu.
On a system
playAt(position: THREE.Vector3): this Move there and restart. The one-call form for a hit or pickup.
play() · pause() · stop() · restart() · clear() stop() lets live particles finish; clear() kills them now.
emit(count: number): this Fire count from every enabled emitter, ignoring rate and duration.
get(name: string): ParticleEmitter | undefined One emitter, by its name in the editor.
isPlaying() · isFinished() isFinished() means stopped and fully drained — what a one-shot's owner polls before releasing it.
setSeed(seed: number): this Reproducible from here on. Each emitter gets seed + index, so they don't correlate.
setPosition(x, y, z): this Move without restarting.
activeParticles · maxParticles · drawCalls Live counters for this system.
On an emitter
settings: ParticleEmitterConfig The live config. Mutating it takes effect on the next frame — this is how you drive an effect from gameplay state.
emit(count) · emitAt(count, x, y, z, vx?, vy?, vz?) Fire now, optionally at an explicit point in the emitter's own space.
setEnabled(enabled: boolean): this Stops simulating and hides it, but keeps it registered and editable.
attached: THREE.Object3D | undefined The scene object it follows. Never modified by the emitter.
activeParticles · maxParticles Live count against the hard cap.
9

Save

💾 Save in the particle toolbar writes src/game/particles.json. The dot on the button means unsaved; Ctrl+Z / Ctrl+Y undo and redo, sharing one stack with the collider editor.

Only the configuration is saved, never live particles. A saved effect is its emitter configs and nothing else — no positions, no ages. That's what makes the file small and diffable, and why a loaded effect starts from its own beginning.

It's a real import in the module graph, so what you author is what runs in the production build — no export step.
