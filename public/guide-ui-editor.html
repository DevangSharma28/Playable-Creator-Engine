System guide

UI Editor

Every pixel of on-screen UI — score, buttons, the joystick, the end card — is a named element in a layout you draw by hand. There is no hardcoded UI anywhere: code only ever looks things up by the name you typed in the editor.

1

Open it

With npm run dev running, click ✏️ Editor in the Engine Room panel (top right). It opens as a transparent overlay on top of the running game, so you're positioning against the real 3D scene, not a mockup. Gameplay pauses while it's open so drag gestures don't fight the joystick.

Two layouts ship. mainLayout.json is what's visible during play; endcardLayout.json is hidden until the game ends, then shown as one group. The toolbar's ⭐ Set as Main and 🏁 Set as Endcard decide which file you're writing.
2

Place and name an element

Add with + Image, + Text, + Rect, + Joystick, or + Group. Drag to position, drag the red handle to resize.

The name is the contract. It's the only thing code uses to find an element, so set it in the Properties panel before you write any. Rename it later and the lookup silently stops matching.

Image
Embedded as base64, so a saved layout is self-contained — no missing-asset step.
Text
Font size is a % of the container's height, so it scales with the screen.
Rect
A coloured box with optional radius/border. What most buttons actually are.
Joystick
Must be named exactly joystick in mainLayout.json — Game.ts looks it up by that name and throws loudly if it's missing.
Group
A container. Nested children position relative to it, and move/resize together.
3

PX or %, and why it matters

Each of X / Y / Width / Height has its own % / PX toggle. This is the single most common source of "it looked fine on my screen".

Should stay centred or proportionally placed
%
Must keep its shape (a circle stays circular)
PX
Full-bleed background reaching real screen edges
% width + height
Fixed inset from a corner, like a 32px margin
PX + corner anchor

A PX value is a physical size measured against the layout's design resolution, scaled by one uniform factor so it never stretches differently per axis. A % value is plain CSS percent against its real container. Position in PX is an offset from the anchor's own point (Unity's anchoredPosition) — a middle-center anchor at 0,0 sits dead centre on any screen shape.

Test at a different aspect ratio before you trust a layout. Use the Portrait / Landscape / Real tabs top-centre. Most layout bugs only appear when the live aspect is far from the design's.
4

Drive it from code

game.ui is the main layout, game.endcardUILayout is the end card. Both are the same UILayout API, and everything addresses elements by the name you typed. 

// src/game/ui/HUD.ts — the real one in this project
export class HUD {
  constructor(
    private readonly main: UILayout,
    private readonly endcard: UILayout
  ) {
    this.endcard.setVisible(false);           // hidden until the game ends
  }

  setScore(collected: number, total: number): void {
    this.main.setText("score", `${collected} / ${total}`);
  }

  hideDragHint(): void {
    this.main.hide("drag-hint");
  }

  showEndCard(won: boolean): void {
    this.endcard.setText("endcard-title", won ? "All coins collected!" : "Nice rolling!");
    this.endcard.setVisible(true);            // shows the whole layout as one group
  }

  // Wire the install button. The handler routes through Cta.open() in
  // Game.ts — never window.open() directly.
  onCtaClick(handler: () => void): void {
    this.endcard.setInteractive("cta-button-bg", handler);
  }
}
Everything is decorative until you say otherwise. Every element is pointer-events: none so it can never steal a touch from the joystick underneath. setInteractive() is what opts one element in.
5

Bind an element to a field

Looking elements up by string works, but a typo fails silently. The Scripts panel lets you drag an element onto a public field instead — declare the field, assign it in the editor, and it's populated at boot. 

// 1. Declare a public field of an element type
export class HUD {
  public moneyIcon: HTMLElement | undefined;

  constructor(private readonly main: UILayout, private readonly endcard: UILayout) {
    // 2. One explicit call resolves every binding for this class.
    //    No reflection behind it — compiled JS classes have none.
    applyBindings(this, "HUD", bindingsData, this.main, this.endcard);

    // 3. moneyIcon is now the real DOM element (or undefined if
    //    nothing was assigned yet — always guard).
    if (this.moneyIcon) this.moneyIcon.style.opacity = "0.5";
  }
}

In the editor: open Scripts, pick ui/HUD.ts, then drag the element from Layers onto the moneyIcon row (or click its ⊙ Pick button).

6

Full API

Reading and writing content
setText(name: string, text: string): void Replace a text element's content.
setImage(name: string, src: string): void Swap an image's source — a data URI or a path.
get(name: string): HTMLElement | undefined The raw element, for anything the API above doesn't cover. Undefined if the name doesn't match.
Visibility
show(name: string): void Show one element.
hide(name: string): void Hide one element.
setVisible(visible: boolean): void Show/hide the whole layout as one group. Individual elements keep their own state underneath.
Interaction
setInteractive(nameOrElement, onClick?): void Opt an element into pointer events and attach a click handler. Accepts a name or the element itself (what a bound field holds).
getJoystick(name): { base, knob } | undefined The two nodes DynamicJoystick needs. You won't normally call this — Game.ts does.
Layout
updateScale(width: number, height: number): void Re-derive every element's geometry for a new container size. Game.ts already calls this on resize — you only need it for a container you own.
7

Save

With the dev server running, 💾 Save writes straight into the project — no download step. ⭐ Set as Main and 🏁 Set as Endcard write the two files the game actually loads.

src/game/ui/ mainLayout.json ← gameplay HUD + joystick endcardLayout.json ← end card, hidden until the game ends bindings.json ← element ↔ script field assignments layouts/ ← saved variants, load from the 📂 menu

Saving triggers a hot reload, and the editor's own state (undo history, unsaved edits) survives it — the page never navigates.

8

When something doesn't work

setText does nothing
Name mismatch — check Properties
Button isn't clickable
Needs setInteractive()
Game throws "missing joystick"
Element must be named joystick
Circle goes oval in landscape
Use PX size, or 🔒 Lock aspect
Bound field is undefined
Not assigned yet, or class name differs
Editor shows stale behaviour
Re-run node scripts/sync-assets.js
That last one catches people out: Vite only watches src/, so edits to tools/ui-editor.html itself aren't picked up automatically.
