System guide

UI Editor

Every pixel of on-screen UI — score, buttons, the joystick, the end card — is a named element in a layout you draw by hand. There is no hardcoded UI anywhere: code only ever looks things up by the name you typed in the editor.

1

Open it

With npm run dev running, click ✏️ Editor in the Engine Room panel (top right). It opens as a transparent overlay on top of the running game, so you're positioning against the real 3D scene, not a mockup. Gameplay pauses while it's open so drag gestures don't fight the joystick.

Two layouts ship. mainLayout.json is what's visible during play; endcardLayout.json is hidden until the game ends, then shown as one group. The toolbar's ⭐ Set as Main and 🏁 Set as Endcard decide which file you're writing.
2

Place and name an element

＋ Insert (or press I) opens the palette. Images come in through the 🖼️ button beside it, since there's nothing to place until you've chosen a file.

Drag to position — it snaps to other elements' edges and centres, and to guides you pull off a ruler. Eight handles resize (dragging pins the opposite edge; Alt scales about the centre, Shift keeps the ratio), and the grip above the box rotates (Shift snaps to 15°).

The name is the contract. It's the only thing code uses to find an element, so set it in the Properties panel before you write any. Rename it later and the lookup silently stops matching — the ✅ badge flags two elements sharing a name, because that makes one of them permanently unreachable.

Text
Font size is a % of the container's height, so it scales with the screen. Outline and shadow are available for titles over busy backgrounds.
Image
Embedded as base64, so a saved layout is self-contained — no missing-asset step.
Rect
A coloured box with optional radius, border, gradient and shadow.
Button
A box that centres a label, with an optional icon. Clickable by default, ships with a pressed state, and can carry actions — often no code needed at all.
Group
A container. Nested children position relative to it, and move/resize together. Turn on Clip contents to use one as a mask.
Progress
A track and a fill, in any of four directions. Drive it with ui.setValue(name, 0…1).
Slider
Draggable at runtime over your own min/max. Each change fires "name:change" through onAction.
Toggle / Checkbox
Flip themselves on click; read with ui.isOn(name).
Sprite
A spritesheet animated in pure CSS — no per-frame JS, so it costs nothing at runtime.
Shape
Star, hexagon, heart and friends, clipped from the box. Scales at any size.
Icon
A single glyph or emoji, sized and coloured like text.
Video
Muted + autoplay by default — the only combination most ad WebViews will actually start without a user gesture. Embedded like every other asset, so keep the clip short.
Joystick
Must be named exactly joystick in mainLayout.json — Game.ts looks it up by that name and throws loudly if it's missing.
3

PX or %, and why it matters

Each of X / Y / Width / Height has its own % / PX toggle. This is the single most common source of "it looked fine on my screen".

Should stay centred or proportionally placed
%
Must keep its shape (a circle stays circular)
PX
Full-bleed background reaching real screen edges
% width + height
Fixed inset from a corner, like a 32px margin
PX + corner anchor

A PX value is a physical size measured against the layout's design resolution, scaled by one uniform factor so it never stretches differently per axis. A % value is plain CSS percent against its real container. Position in PX is an offset from the anchor's own point (Unity's anchoredPosition) — a middle-center anchor at 0,0 sits dead centre on any screen shape.

Test at a different aspect ratio before you trust a layout. Use the Portrait / Landscape / Real tabs top-centre. Most layout bugs only appear when the live aspect is far from the design's.
4

The tools around the canvas

Everything lives in the one top toolbar — there is no floating bar over the artboard. Press ? for the full shortcut list.

Align & distribute
Select two or more, then ⌗. Aligns against the selection's own bounding box (not the canvas — those are separate buttons), spaces evenly, or matches sizes.
Rulers & guides
R. Drag off a ruler to drop a guide; drop it back at the edge to discard. Click the corner square to clear them all.
Snapping
S. Sibling edges and centres, container centres, and your guides. The highlighted line is the one that actually caught.
Zoom & pan
Ctrl+wheel (or trackpad pinch) to zoom, Space+drag or middle-drag to pan, Ctrl+0 to reset.
Safe area
A. Overlays the inset that notches and ad-network chrome eat into. A guide, not a constraint.
Animation preview
P. Off by default — elements moving while you position them is the opposite of useful.
Lock
Ctrl+L. A locked element can't be grabbed or marquee-selected on the canvas, but stays fully editable from Layers. For finished backgrounds.
Assets / Prefabs
Sidebar tabs. Assets is a reusable image library; Prefabs stores a selection you can stamp back in later — as a copy, so edits don't flow back.
Autosave
Mirrors your work to browser storage and offers it back if the tab dies. It never writes a project file — it is not a substitute for Save.
The ✅ badge is worth watching. It catches what otherwise only surfaces as a broken ad much later: duplicate names, missing image sources, zero-size or fully-transparent elements, a font size of 0, and actions pointing at an element you've since deleted. Click a finding to jump to it.
5

Make a button work without code

A button's Actions section handles the common cases outright. show, hide, toggleVisible and setText run entirely in the runtime; cta fires the configured store link.

For anything game-specific, use emit: it sends a named event you handle in one place, which is how a designed button triggers your logic without the engine ever learning your game's vocabulary. 

ui.onAction((event, element) => {
  if (event === "start-game") this.begin();
  if (event === "volume:change") this.setVolume(ui.getValue("volume"));
});

States sit next to it — hover, pressed and disabled each take a small visual override (colour, opacity, scale). A new button ships with a pressed state already, because a button with no press feedback feels broken on touch.

6

Drive it from code

game.ui is the main layout, game.endcardUILayout is the end card. Both are the same UILayout API, and everything addresses elements by the name you typed. 

// src/game/ui/HUD.ts — the real one in this project
export class HUD {
  constructor(
    private readonly main: UILayout,
    private readonly endcard: UILayout
  ) {
    this.endcard.setVisible(false);           // hidden until the game ends
  }

  setScore(collected: number, total: number): void {
    this.main.setText("score", `${collected} / ${total}`);
  }

  hideDragHint(): void {
    this.main.hide("drag-hint");
  }

  showEndCard(won: boolean): void {
    this.endcard.setText("endcard-title", won ? "All coins collected!" : "Nice rolling!");
    this.endcard.setVisible(true);            // shows the whole layout as one group
  }

  // Wire the install button. The handler routes through Cta.open() in
  // Game.ts — never window.open() directly.
  onCtaClick(handler: () => void): void {
    this.endcard.setInteractive("cta-button-bg", handler);
  }
}
Everything is decorative until you say otherwise. Every element is pointer-events: none so it can never steal a touch from the joystick underneath. setInteractive() is what opts one element in.
7

Bind an element to a field

Looking elements up by string works, but a typo fails silently. The Scripts panel lets you drag an element onto a public field instead — declare the field, assign it in the editor, and it's populated at boot. 

// 1. Declare a public field of an element type
export class HUD {
  public moneyIcon: HTMLElement | undefined;

  constructor(private readonly main: UILayout, private readonly endcard: UILayout) {
    // 2. One explicit call resolves every binding for this class.
    //    No reflection behind it — compiled JS classes have none.
    applyBindings(this, "HUD", bindingsData, this.main, this.endcard);

    // 3. moneyIcon is now the real DOM element (or undefined if
    //    nothing was assigned yet — always guard).
    if (this.moneyIcon) this.moneyIcon.style.opacity = "0.5";
  }
}

In the editor: open Scripts, pick ui/HUD.ts, then drag the element from Layers onto the moneyIcon row (or click its ⊙ Pick button).

8

Full API

Reading and writing content
setText(name: string, text: string): void Replace a text element's content.
setImage(name: string, src: string): void Swap an image's source — a data URI or a path.
get(name: string): HTMLElement | undefined The raw element, for anything the API above doesn't cover. Undefined if the name doesn't match.
Visibility
show(name: string): void Show one element.
hide(name: string): void Hide one element.
setVisible(visible: boolean): void Show/hide the whole layout as one group. Individual elements keep their own state underneath.
Controls
setValue(name: string, value: number): void Drive a progress fill (0–1) or a slider (in its own min/max, normalised for you). Out-of-range values clamp rather than overflowing the track.
getValue(name: string): number | undefined Current value, in the units you authored — not the normalised fraction.
isOn(name: string): boolean | undefined A toggle or checkbox's state. Both flip themselves on click; you only read them.
Interaction
setInteractive(nameOrElement, onClick?): void Opt an element into pointer events and attach a click handler. Accepts a name or the element itself (what a bound field holds).
onAction(handler: (event, element) => void): void Receives emit actions authored in the editor, the cta action, and slider changes as "name:change". This is the one seam that lets a designed button do something game-specific — the engine never learns your vocabulary.
getJoystick(name): { base, knob } | undefined The two nodes DynamicJoystick needs. You won't normally call this — Game.ts does.
Layout & lifecycle
updateScale(width: number, height: number): void Re-derive every element's geometry for a new container size. Game.ts already calls this on resize — you only need it for a container you own.
dispose(): void Drops every listener this layout attached. Game.dispose() already calls it; it matters because those handlers close over the Game, so on a dev hot reload leaving them attached keeps a disposed Game alive.
9

Save

With the dev server running, 💾 Save writes straight into the project — no download step. The button turns green with a ✓ and names what it wrote, so you get confirmation where you clicked rather than having to spot a status label at the far end of the toolbar. ⭐ Main and 🏁 Endcard write the two files the game actually loads.

src/game/ui/ mainLayout.json ← gameplay HUD + joystick endcardLayout.json ← end card, hidden until the game ends bindings.json ← element ↔ script field assignments layouts/ ← saved variants, load from the 📂 menu

Saving triggers a hot reload, and the editor's own state (undo history, unsaved edits) survives it — the page never navigates.
