System guide

Colliders & Areas

Trigger zones, pickup radii, and walls that actually stop you. It answers one question continuously — which volumes overlap right now — and turns the frame-to-frame change into enter/stay/exit events.

This is not physics. No rigidbodies, no mass, no velocity, no gravity, no solver. Nothing here moves a scene object unless you call moveAndSlide. That's a deliberate trade: a real physics engine is hundreds of kilobytes of WASM for a system whose job is "tell me when the player reaches the zone". This costs a few kilobytes and some dot products.
1

Place one in the editor

Open the 3D editor (3D View in the Engine Room), then click 🧊 in the toolbar or press K. A second toolbar row appears.

＋ Box / Sphere / Cylinder
Creates a collider. With a scene object selected, it's attached to it and fitted to its real geometry bounds — which is what you want almost every time.
👁 Volumes
Hide the wireframes without stopping detection — useful when a volume covers what you're aiming at.
💾 Save
Writes src/game/colliders.json. The dot on the button means unsaved.
↶ / ↷
Undo / redo, or Ctrl+Z / Ctrl+Y.

Colours tell you the state at a glance: green solid, cyan trigger, grey disabled, red overlapping something right now.

Colliders live in their own COLLIDERS group in the Hierarchy, never inside your model's tree. They attach to a scene object rather than parent under it, so the attachment survives re-exporting the GLB.
2

Trigger or solid — the only distinction that matters

isTrigger: true

A volume you walk through. Reports overlaps via onTrigger* and never pushes anything. Zones, pickups, checkpoints.

isTrigger: false

Solid. Contributes a push in moveAndSlide, and reports to other solids via onCollision*. Walls, props.

If either side of a pair is a trigger, only trigger events fire — a zone never also reports as a collision, and the solid that walked into it is told nothing.

3

React to a zone

Find the collider by the name you gave it in the editor, then subscribe. The first argument is an optional tag filter, which saves every handler from opening with an if. 

import { Ion } from "../engine/Ion";
import type { Collider, ColliderEventHandle } from "../engine/collision";

export class ShopZone {
  private readonly handles: ColliderEventHandle[] = [];
  private inside = false;

  wire(): void {
    const zone = Ion.colliders.getByName("ShopZone");
    if (!zone) return;                          // editor data — never assume it exists

    // Fires once, on the frame the overlap begins.
    this.handles.push(
      zone.onTriggerEnter("Player", (other) => {
        this.inside = true;
        hud.showPrompt("Press to buy");
      })
    );

    // Every frame after that, while it holds.
    this.handles.push(
      zone.onTriggerStay("Player", () => score.tickBonus())
    );

    // Once when it ends — including if the other collider is
    // disabled or destroyed while still inside.
    this.handles.push(
      zone.onTriggerExit("Player", () => {
        this.inside = false;
        hud.hidePrompt();
      })
    );
  }

  // Call from Game.dispose() so a hot reload can't leave old
  // handlers listening. Every on* returns its unsubscribe.
  dispose(): void {
    for (const off of this.handles) off();
    this.handles.length = 0;
  }
}
Exit always fires. Disabling, destroying, or removing the other collider from the scene all produce a real exit event. That's what stops the classic bug where a flag gets set on enter and never cleared.
4

Create one in code

Anything an entity owns should be created where it builds its model. Ion is bound before Game.create() precisely so a constructor can do this. 

// src/game/entities/Player.ts
this.collider = Ion.colliders.cylinder({
  name: "Player Collider",
  tag: "Player",
  radius: 0.4,
  height: 1.8,
  attachTo: this.group,     // follows the group's world matrix every frame
  position: [0, 0.9, 0],    // half the height, so it stands on the ground
});
A code-created collider must not end up in colliders.json. It carries persisted = false and the editor's save skips it — otherwise the next boot would build a second one next to the one your script creates.
5

Make walls stop the player

Detection alone never moves anything. moveAndSlide is the bridge: it applies your movement, then pushes back out of every solid collider you ended up inside. 

const UP = new THREE.Vector3(0, 1, 0);
const moveDelta = new THREE.Vector3();   // reused — update() is a hot path

update(dt: number, axis: { x: number; y: number }): void {
  moveDelta.set(axis.x * this.speed * dt, 0, axis.y * this.speed * dt);

  Ion.colliders.moveAndSlide(
    this.collider,          // must be attached to the object owning `position`
    this.player.position,   // mutated in place
    moveDelta,
    { up: UP }              // see below — always pass this for anything that walks
  );
}

Sliding falls out for free. The push is perpendicular to the surface, so the component of your movement along the wall survives untouched.

Always pass up for a character. Without it, every escape axis is fair game — and the cheapest way out of a knee-high kerb is genuinely over the top, so your player climbs the scenery instead of being stopped by it. Measured: a 1.8-tall cylinder in a 0.5-tall kerb resolves to (0, 0.5, 0) without up and (0.7, 0, 0) with it.
6

Tags vs masks

Two different filters, and worth keeping straight.

mask — broad phase

Which pairs are evaluated at all. Masks are ANDed, so each side must accept the other; empty means "accept anything". A rejected pair never reaches an intersection test, so this is a real optimisation.

tag argument — handler filter

Which handlers hear about an overlap that already happened. Saves writing if (other.tag !== "Player") return; in every handler.

Usually they agree. They're separate because a zone that wants to see several tags but react differently to each needs a wide mask and narrow handlers.

7

Full API

Finding colliders — Ion.colliders
getByName(name: string): Collider | undefined By the name typed in the editor. Keep names unique.
getByTag(tag: string): Collider[] Every collider carrying that tag.
overlapSphere(center, radius, tag?): Collider[] Ad-hoc "what's near me right now" — for the question you ask once, not every frame.
queryPoint(point, tag?): Collider[] Colliders whose volume contains a world point.
Creating
box({ name, tag, isTrigger, mask, size, attachTo, position, rotation, scale }) size is full width/height/depth. Rotation is in degrees.
sphere({ …, radius }) Same options, plus radius.
cylinder({ …, radius, height }) The character shape — rotation-invariant about up, unlike a box, but with real height, unlike a sphere.
Movement and blocking
moveAndSlide(collider, position, delta, { up?, tags?, iterations? }) Applies the delta then pushes out of solids. Mutates position, returns the movement actually applied. Defaults to 2 push passes so inside corners settle.
depenetrate(collider, options?, out?): Vector3 The push without applying it — for anything that isn't a straightforward character move.
getStats(): ColliderStats total, enabled, narrowTests, activePairs — measured, not estimated.
On a collider
onTriggerEnter(tag?, handler) → unsubscribe Also onTriggerStay, onTriggerExit, and the onCollision* trio for solid-vs-solid. Always keep the returned function.
setEnabled(enabled: boolean): this Turning one off mid-overlap fires exit on every pair it was in.
checkTag(tag: string): boolean Preferred over collider.tag === "…" — keeps working if tags ever become a list.
attachToObject(object, preserveWorld = true): this Follow a different object. Does not move the collider — the offset is recomputed so the volume stays where it is in the world.
overlaps(other) · containsPoint(point) · worldCenter Direct queries against the last synced world shape.
destroy(): void Fires exit on anything it was overlapping, then unregisters. Idempotent.
